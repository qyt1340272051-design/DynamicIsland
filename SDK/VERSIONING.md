# 版本和兼容策略草案

状态：实验性，未发布稳定 SDK；不修改现有 Host wire 协议。

| 标识 | 当前值 | 含义 |
| --- | --- | --- |
| SDK 工作草案 | `0.1.0-experimental` | 本目录作者工具和类型的准备版本，不能当作稳定性承诺。 |
| Manifest `schemaVersion` | `1` | Host 解析的包格式；未知字段和声明拒绝。 |
| `island.apiVersion` / 方法 namespace | `1.0.0` | 当前桥接协议标识；不单独授予能力或权限。 |
| Manifest `minimumHostVersion` | Hello 为 `0.6.0` | 安装时的最低 Host 版本门槛；不能省略。 |

本草案只整理现有两官方插件使用过的接口。两款官方插件的实机依赖已于 2026-10-19 满足，范围见[验证说明](docs/verification.md)；这只关闭原先置条件，T38 的稳定版本复核、版本选择和发布仍待完成。有限类型和 Schema 不能覆盖主程序的所有运行状态，也不能提升 SuperIsland 的兼容等级。

T39 本日首次作者走查暴露了交互式 zsh 粘贴完整 Bash 源码的问题；Quick Start 已改为首个可复制的单行入口，修正后的协助功能复测已通过，用户自行打包、安装、启用并确认计数更新。该修正不更改 wire 协议、Manifest schema 或权限；首次独立体验及约十分钟目标仍待复测验证。

稳定版本发布前，草案可以调整，但每项变化必须同步类型、示例、Schema、校验器和契约测试，并记录迁移方法。即使只新增 Host 声明，也不能让旧包自动取得 capability 或授权。代码 / Manifest 改变后的授权失效继续由 Host 执行。

未来稳定版本应分别管理 SDK 和协议版本：在现有严格解码中新增必填字段、修改默认行为、删除方法或改变返回类型均需显式新协议 / 迁移策略，不能仅更新文档而让旧 Host 误收。保留现有协议的兼容实现后再扩大支持范围，且必须补充真实插件验证。发布或托管本 SDK、上传包及 Registry 条目是后续独立步骤，本轮没有执行。
