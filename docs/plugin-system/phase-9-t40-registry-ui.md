# T40 子步骤：发现窗口与共享安装流程

日期：2026-10-18。基线 `23a039c`。本步完成可自动执行的发现 UI、App 接线及下载取消；T40 继续 `in progress`，真实发布条目、网络端到端验收及 T38 依赖仍保留。

## 实现与用户流程

设置页和独立插件管理窗口都提供「发现」。[PluginRegistryModel / View](../../DynamicIsland/Plugins/PluginRegistryUI.swift)默认打开时保持离线，用户点击「刷新目录」才读取本项目 main 分支的 Registry/registry.json。初始、加载、取消中、成功空目录、请求失败、兼容及最低 Host 不兼容分别展示；HTTP 不可用不会冒充空目录。来源以文本显示，不标识为已认证。

可下载条目必须与当前成功目录中的完整条目相等，并满足最低 Host。点击「下载并查看」显示原安装窗口，经过正式 RegistryClient、SHA-256、ZIP、Validator 与 Manifest 复核后展示原 review。之后仍需用户点击「安装插件」；安装保持停用，权限仍是 requested。目录字段不会自动授予、启用或升级插件。

[PluginInstallerModel](../../DynamicIsland/Plugins/PluginInstallerUI.swift)在任何 await 前占用与本地导入相同的槽位。目录下载、本地导入和 Finder 队列不能互相替换 review。下载阶段可取消；关安装窗口会等待下载 / 清理完成后关闭。即使取消后底层迟到返回 review，也会先清理该精确 review；清理失败保留它并阻止新导入，明确重试后恢复。

关闭发现窗口会取消目录刷新，迟到目录不会覆盖状态；已开始的包下载由安装窗口管理。退出应用先停止目录刷新，再执行原导入协调器的 shutdown。若清理失败导致退出取消，发现模型恢复可用；关闭窗口没有后台轮询或自动重试。

App 仅在初始插件发现及导入协调器配置之后开放 Registry 模型，避免在启动发现完成前插入安装。网络和安装操作仍由现有 actor / Host 服务处理，SwiftUI 仅持有 MainActor 状态。

## 阶段检查与边界

- 复用 T34 安装事务、权限预览与停用提交，未引入第二套安装器或 Runtime API；共享占用状态覆盖取消和退出竞争。
- 无后台刷新；用户刷新与下载均有现有网络体积、超时和并发限制。没有增加轮询计时器。
- 错误文案固定映射，不回显临时路径、底层异常或下载服务响应；source 仅可选中文本。
- 本步回滚可移除发现入口、Registry 模型与下载阶段接线，原本地导入接口不变；不自动修改已安装插件或权限记录。
- 完整 CI / Release / 签名结果已归档；不以模型和截图测试代替公开网络或真实发布验收。阶段统一边界见 [Phase 9 检查](phase-9-acceptance.md)。
