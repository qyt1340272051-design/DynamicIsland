# U06 — 播放期间悬停无响应（2026-10-27）

用户反馈：音乐播放时，鼠标移入岛有概率没有反应，或停在展开前的轻微膨胀态；进一步确认卡住时任何位置均无响应。修正目标为 App 0.6.1 / build12。

## 已复现的机制

原 30 Hz `.common` 计时器在回调中再创建 MainActor Task，350 ms 展开延时也通过 Task 完成。当一个 MainActor 作业同步进入 AppKit 的 tracking 事件循环时，计时器可继续触发，但新 MainActor 作业要等外层作业返回。这分别会延后鼠标进入采样和已进入后的正式展开。新增原生 tracking 回归在旧代码上保持 compact 并失败，修正后可在同一事件循环内展开。

另有宽 compact 的几何问题：展开页较窄时，原先接纳的两翼被立即排除，静止指针触发收起与重新等待。当前设备的普通音乐尺寸没有这个宽度反转，因此不将它单独视为用户本次故障的原因。

只读进程采样未捕获正在卡住的现场；样本主要位于 SwiftUI / RenderBox 提交，没有看到主线程等待媒体辅助进程。该样本不用于认定偶发问题的唯一根因。

## 修改

- 鼠标采样直接在主 RunLoop 的 common 模式回调内执行，避免每帧累积异步作业。
- 展开延时改为同一主事件循环的一次性计时器，保留 350 ms 延时；离开、隐藏、菜单进入和计时完成等路径仍会取消，并检查计时器身份、可见性和抑制状态。
- 采样会核对 ViewModel 与面板缓存，静止指针也能恢复已丢失的待展开状态；计时完成确认后的“移出再进入”规则保留。
- 一次悬停期间保留包括轻微膨胀反馈的薄入口区域，真实移出或屏幕几何变化后清除。区域按两个矩形分别判断，不将透明侧角扩大为命中范围。
- compact 波形隐藏后停止重复符号动画。

## 验证范围

新增回归覆盖 tracking 内展开与移出、提前离开、缓存分歧恢复、隐藏后重开、播放中从两翼与中央反复收展，以及比展开页更宽的音乐 compact。驻留时间超过外壳动画和多次鼠标采样，并核对每次展开仅一次触觉反馈；还覆盖延时内移到膨胀区域底边。

首轮完整回归执行 1208 项，其中 1203 通过、3 跳过、2 个测试失败。两项既有布局检查在单独运行时也复现：跨缩放原生按钮的位置比较未计算基准截图自身的像素舍入误差；音乐截图把不同的小数高度分别截为整数像素，导致两个位图使用不同的栅格比例。前者按两次测量各自的半像素精度传播误差，保留原生大小、转换和命中检查；后者改用顶部对齐的整数像素画布，保留原 Renderer 的小数布局、2% 像素数量上限和完整内容断言。布局比较固定滚动相位，动态滚动仍由 U05 的真实窗口测试覆盖。两项定向复验均通过，随后重新执行完整检查。

测试与普通 App 运行结果记录在[证据目录](evidence/u06-hover-tracking-20261027/README.md)。此次不更改网易云插件文件、已授予权限、播放来源，也不发送播放控制命令。既有 U02/U03、T01–T40 和公开发布状态不因此改变。

最终完整检查 1208 项，其中 1205 通过、3 跳过、0 失败，Release 构建与严格签名验证通过。旧 build11 经正常退出后，已启动 `build/u06/Dynamic Island.app`；真实设置页显示 0.6.1 / 12、网易云音乐来源、读取 / 控制均“已允许”。当前实机为 1710×1112，早先只读采样为 2560×1664；本轮未切换系统分辨率。自动化坐标点击不改变 `NSEvent.mouseLocation`，实体鼠标验收单独进行。2026-10-27，用户针对移入停留约 1 秒、移出并重新移入数次的复验明确回复“现在可以正常展开”，当前设备 build12 的实体鼠标收展确认通过。
