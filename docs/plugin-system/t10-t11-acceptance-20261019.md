## T10 DesignTokens：完成标准已满足

## T11 Presentation Model：保留一个具体缺口

[计划 T11](DevelopmentPlan.md#t11-presentation-model)要求纯数据三态、每态复杂度 / 高度限制、缺失形态降级，最终能让同一 Timer Activity 从 minimal 平滑进入 compact / expanded。

已满足的部分：

- [ActivityPresentation](../../DynamicIsland/Core/Activity/IslandActivity.swift)包含三个可选节点树，不携带窗口宽高；[HostPolicy](../../DynamicIsland/IslandUI/ActivityPresentationPolicy.swift)规定复杂度、高度和仅向较简单已提供树降级的规则。
- [Presentation 测试](../../DynamicIslandTests/ActivityPresentationTests.swift)覆盖旧 JSON、计时三态、缺失 / 非法 / 超限回退及不含窗口尺寸。[Renderer 测试](../../DynamicIslandTests/IslandRendererTests.swift)在同一 NSHostingView 依次渲染三态；[真实 Node Bridge 测试](../../DynamicIslandTests/PluginIslandNodeBridgeTests.swift)验证同一 VM 产生的 Activity 在三态更新时保持实例身份。它们都是自动化 Host 验证，不能据此声称连续真实动画已验收。
- [T35 实机](evidence/t35-manual-20261019/result.json)已确认真实计时的 expanded / compact、相机两翼和自然结束；[Phase 3](phase-3-acceptance.md)已确认一般抢占恢复动画及 Reduce Motion。

归并基点发现的缺口：正式 [IslandView](../../DynamicIsland/IslandView.swift)只将 `.compact` 与 `.expanded` 传入 Renderer。`minimal` 虽可作为缺失 compact 的回退树，Renderer 的 mode 仍是 compact；没有归档同一真实 Timer Activity 的 minimal → compact → expanded 连续显示 / 动画记录。两翼图标和时间是一个多节点 compact 布局，不能改名计作 minimal。

T11 因此保持 `in progress`。下一步应由 Host 明确选择有效收起布局，把真正 minimal 的单叶内容放到相机安全翼中，再以同一计时引用和实例验证从 minimal 到 compact / expanded 的可见过渡。沿用现有全局收起 / 展开窗口状态即可，不需要新增用户切换开关、插件窗口控制或 Pomodoro 专用 Swift。

### T11 最小改动（定向回归已通过，实机待验收）

- `ActivityPresentation.effectiveCollapsedMode` 优先选择合格 compact；缺失或不合格时保留合格 minimal；两者均缺失时继续使用原 compact 摘要回退。
- `IslandRenderer.collapsedRegionSize` 仅把 minimal 的区域限制为 Host 外壳与保留中心之间的右翼；非有限或没有安全宽度时不绘制在相机上。
- 正式 `IslandView` 使用同一个实例绑定 Renderer，保留原动作 / 倒计时解析器；按有效模式动画切换分配区域。全局窗口仍只有收起 / 展开上下文。
- 新增 / 扩展的测试分别覆盖模式降级、无安全翼的尺寸边界，以及正式 IslandView 中 minimal 真实像素位置、同实例更新 compact 和 Host 展开。像素测试使用受控 Activity；不将它写成真实计时或连续动画已经通过。

代码已写入工作区；首次完整 CI 中该新增像素测试的准备步骤失败，修正说明见下节。应在定向回归及下述真实计时验收后再决定关闭 T11。
