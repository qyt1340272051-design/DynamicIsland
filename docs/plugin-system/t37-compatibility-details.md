# T37 子步骤：Host 兼容详情

日期：2026-10-17。接续[展示请求](t37-presentation-requests.md)。本页记录兼容等级、范围限制与最近成功布局的报告；T37 仍为 `in progress`，真实上游样本验收见[来源审计](t37-upstream-acceptance-audit.md)。

## 报告来源和生命周期

`PluginCompatibilitySnapshot` 只保存 Host 有限枚举，不接受插件自行声明的等级、任意错误文本或日志。原生模式显示「原生 · JavaScriptCore」；当前 SuperIsland 子集始终显示「有限兼容 · SuperIsland」。一次布局没有发生显示替代，也不能提升整个协议的等级。

静态范围包括六类限制：有界视图、同步回调、由 Host 裁决的展示请求、缺少上游窗口状态、缺少上游资源接口，以及 Host 驱动的刷新。安装预览只读取已验证 Manifest 的 engine 生成静态说明，不运行暂存包，也不借用同 ID 已安装包的报告。

管理页另显示本次执行的三种状态：

| 状态 | 含义 |
| --- | --- |
| 当前未运行 | 本次没有执行中的报告；启用偏好不能证明正在执行。 |
| 运行中，尚无成功布局 | Host 已发放新执行 token，尚未接受兼容布局。 |
| 最近成功布局 | 本次执行最近一次成功发布的 compact / expanded 转换观察。 |

两份布局的显示替代取并集，最多八种固定原因。下一次成功布局会替换这个集合；失败转换、能力拒绝、配额和限速拒绝不覆盖旧结果。没有替代时明确说明仍受静态范围限制。报告不是兼容性认证，也不表示当前布局一定是 Host 正在选择的前台 Activity。

查询要求完整的 `ValidatedPluginPackage` 相等，包括入口字节；同 ID、版本与 Manifest 但代码不同的包不能读取旧报告。写入还要求当前私有执行 token 和显式 SuperIsland 模式。停用、暂停、停止、失败清理和卸载会清除动态结果；恢复执行重新从「尚无成功布局」开始。

## 更新与界面

只有普通 Activity 发布或更新成功、当前实例句柄捕获成功后才记录观察。记录通知后再检查当前执行，防止同步停用或换代返回过期成功。相同观察不会反复通知管理页，也不会重启插件或触发重新发现。

本轮审查补修环境恢复通知：唤醒或低电恢复发放新 token 后，只有 Entry 和 token 仍有效才通知；同步停止、替换或启动失败不发布旧执行的开始状态。

Native 保持紧凑元数据；SuperIsland 在可滚动详情中显示状态、最近布局替代与兼容范围。窗口和最低尺寸维持原约定；权限的逐项确认仍由既有管理流程执行。
