## 当前基线采样方法

本次使用已有普通 Release 的隔离副本，身份和签名见 [App 预检](evidence/t02-t08-20261019/app-preflight.json)。它与 2026-10-18 完整 CI 的 Release 可执行文件一致；`253c588` 至准备时 HEAD 的生产源码无差异。副本有独立 bundle ID，保留普通 Sandbox / hardened runtime / JIT，删除文档和 URL handler；未重编、修改或启动生产 App。

[只读采样入口](../../Scripts/measure-activity-baseline.py)要求显式 PID 与完整可执行路径，核对进程所有者、开始时间及可执行 SHA256。先编译外部 observer，再静置 **300 秒**、采样 **300 秒**；窗口内不构建、不跑测试。每五秒读取 libproc rusage v6，使用包含睡眠的单调时钟、真实 timebase 和累计进程计数。身份变化、计数回退、退出或超过十五秒的采样间隔会使窗口无效。

[通用 observer](../../Scripts/ActivityProcessSampler.swift)源自冻结的 T31 采样代码，将允许的最短窗口从 900 秒改为 300 秒，新增准确的零插件标签并调整帮助文字，计数、身份、时钟和异常判定算法不变；[工具核对](evidence/t02-t08-20261019/measurement-tool-review.json)保留来源哈希。历史两组 T31 原始计数也通过[独立复算脚本](../../Scripts/analyze-activity-baseline.py)重新计算，均与原摘要一致。

可重复命令如下；先用实际隔离副本的 PID 和路径替换参数，输出目录必须全新。`--build-note` 写入实际构建来源；观察时 HEAD 与二进制构建身份分开记录。

```sh
python3 Scripts/measure-activity-baseline.py \
  --pid <实际PID> \
  --expected-executable "/隔离副本.app/Contents/MacOS/Dynamic Island" \
  --output-dir /tmp/dynamic-island-baseline-new \
  --phase no-plugins \
  --warmup-seconds 300 --seconds 300 \
  --build-note "实际Release来源、提交与构建日志" \
  --scenario-note "实际显示器、电源、音乐、插件数量与后台负载"
python3 Scripts/analyze-activity-baseline.py \
  --raw /tmp/dynamic-island-baseline-new/samples.jsonl \
  --summary /tmp/dynamic-island-baseline-new/summary.json \
  --output /tmp/dynamic-island-baseline-new/counter-review.json
```

`no-plugins`、`installed-disabled`、`installed-running` 分别表示零安装、已安装但全停用、存在运行插件；须根据实际状态选择。

菜单的隐藏 / 显示切换本轮没有完成：CUA 菜单 AX 索引反复失效，不能据此判定 App 有问题，也不能写为切换已通过。针对既有任务记录的检索未找到可明确替代的实际菜单切换完成证据；Phase 3 的“隐藏菜单栏”是系统菜单栏场景，不等于 App 的隐藏 / 显示开关。

计数覆盖单进程 CPU、physical footprint、wakeups、I/O 与内核归属 CPU 能耗。内核归属 CPU 功率不等于 Activity Monitor 的 Energy Impact、整机或电池电耗，也没有包含 GPU、屏幕、网络的全部代价。静置期间若有音乐或系统事件，必须如实记录，不能仅因没有点击就声称纯空闲。

T31 的[真实后台对照](evidence/t31-background-20261014.md)仍代表旧 Host、单机、20 个相同 scheduler-only 插件、一次顺序对照：平均单核 CPU 1.5598% → 1.9437%，归属 CPU 功率 1.6954 → 3.0869 mW，内存峰值 48.80 → 149.19 MiB。它支持该工作负载下的工程结论；本次零插件基线与它的 Host / 安装数 / 时长不同，不能直接计算成“重构前后回退百分比”。

缺少 Phase 0 同机重构前的原始 App 计数是永久的历史数据边界。本次建立可供后续阶段重复比较的当前基线，不回填旧记录，不由一组短窗口推断长期无泄漏，也不重新要求已由用户确认的多屏和睡眠项目。

本次可执行身份属于本轮 UI 修正前冻结的普通 Release；后续源码修改不能自动继承本次资源数值，完成新构建后可用同一协议作比较。
