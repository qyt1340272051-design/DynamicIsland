# U05 — 长音乐信息布局与往返滚动（2026-10-27）

用户报告：网易云已授权且能够读取歌曲，但展开音乐页只显示一行曲名。随后要求文字过长时在固定位置左右循环显示。目标为 App 0.6.1 / build11；不修改插件代码、权限或播放来源。

## 原因与修正

`ViewThatFits` 同时按水平、垂直方向检查理想尺寸。原先完整音乐树在没有真实宽度约束的情况下测量；较长曲名或歌手 / 专辑会让理想宽度超过内容区，整树因此被替换为仅显示曲名的摘要。数据与按钮声明仍在，单纯缺少封面不会触发此现象。

修正为先给展开布局实际的内容宽度，再进行高度适配。文字不能通过理想宽度挤掉封面、进度、播放或音量控件；原有紧凑布局及垂直回退仍保留。

展开态文字由原生单行文本测量：短文字保持字号与固有宽度；超宽文字仅在自身裁切区域内以每设计秒约 24 pt 往返，两端各停留 1 秒。不会带动其他控件或挤占时间标签与进度条的空间。完整文本作为单个无障碍标签保留；收起、隐藏、无溢出或启用“减少动态效果”时不运行滚动时间线。进度刷新不会重置未变化的曲名滚动。

## 验证

- 修复前已重现用户曲名及较长副标题的布局回退：完整音乐树通过 schema / HostPolicy，但封面区域实际绘制像素为 0。
- 新增长曲名、长副标题、Unicode、缺图、错误提示、相同窗口短→长→短切换回归，覆盖 0.88 与 1.54 倍实际排版密度。
- 新增往返停顿、偏移限界、可见性 / 减少动态效果、短文本固有宽度、固定区域裁切，以及真实窗口内时间推进后的不同截图检查。

完整回归 1201 项、3 跳过、0 失败，Release 构建成功。随后补充收起态文字的无障碍隐藏及静态文本语义，最终源码定向复验 33 项、0 失败，并再次构建 Release；两批不合并计数。原生可见窗口中已比较初始静止帧与 1.75 秒后移动帧，确认固定区域内确有位移且不越界。

当前已实际启动经签名核验的 0.6.1/build11，并通过普通设置界面核对版本、网易云来源及两项原有授权；收起时无展开文字残留于无障碍树。本次未发送任何播放控制命令，未改变或撤销用户本次自行授予的网易云权限。截图、两批测试范围与记录见[证据目录](evidence/u05-long-metadata-20261027/README.md)。
